# SLAS prototype V2

Live preview: https://alinachandel-max.github.io/slas-prototype/v2/

A separate concept with the existing SLAS visual components and accordion motion. The original prototype at the site root is unchanged.

## Try the flow

Start a new application, confirm eligibility and email, then complete student verification, contacts, funding, bank details and documents. Admission evidence is required to submit, but can be added after other sections. Demo email code: 123456. Any matching passwords with at least8characters work; this is not real authentication.

Demo options also cover returning students, a previous submitted application with a new academic session, closed-session drafts, failed bank checks, save failures and interrupted submission.

## Data and limits

This is a frontend prototype. It sends no identity checks, email, bank request or application to NELFUND. Use fictional details and sample documents. Draft answers and uploaded files are saved only in this browser on this device; passwords and codes are excluded. Clearing browser data removes them. Demo sign-in is not an account-security mechanism. Clear demo data is available under Demo options.

Academic sessions, fees, the returned student identity and status transitions are examples. Early account creation, draft APIs, verification freshness, bank-change policy, document alternatives and final legal copy require product/backend confirmation. Bank fields and Admission Letter remain required in this concept. Upkeep depends on Tuition Token release after approval; token release screens are outside this prototype.
